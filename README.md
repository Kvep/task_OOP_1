# Система управления складом (Вариант 8)
## Описание модели
Данный проект реализует предметную область «Склад: партии и сроки годности» на языке Java 21.

### Основные сущности:
*   **Product** (Товар) — record с уникальным артикулом, названием, категорией и ценой в копейках.
*   **Category** (Категория) — перечисление, содержащее требуемый температурный режим и срок хранения по умолчанию.
*   **TemperatureMode** (Температурный режим) — перечисление режимов хранения (Морозильный, Охлаждаемый, Обычный).
*   **Batch** (Партия) — record с номером, товаром, датами производства/истечения и количеством. 
*   **Warehouse** (Склад) — сервисный класс, управляющий партиями.

### Реализованный функционал:
**Базовый уровень:**
1.  Приёмка партии с проверкой совместимости температурных режимов.
2.  Отгрузка по правилу FEFO (First Expired, First Out) — первой уходит партия с ближайшим сроком годности.
3.  Получение остатка товара на заданную дату (без учёта просроченных).
4.  Получение списка просроченных партий на дату.
5.  Выброс исключений при попытке отгрузить товар сверх остатка.

**Повышенный уровень:**
1.  Резервирование партий под заказ с возможностью отмены по таймауту.
2.  Отчёт «сгорит в ближайшие N дней» с расчётом суммы потерь в копейках.
3.  Проверка совместимости категории товара и температурного режима зоны склада.

### Архитектура и особенности:
*   Используются возможности **Java 21**: `record`, `sealed interface`, `switch`, паттерн-матчинг, Stream API.
*   Закрытая иерархия операций через `sealed interface StockOperation` (`Receipt`, `Shipment`, `Reservation`, `ReservationCancel`).
*   Собственная иерархия исключений (наследники `WarehouseException`).
*   Строгая инкапсуляция: внутренние списки партий и резервов не отдаются наружу (возвращаются неизменяемые копии).
*   Деньги хранятся и считаются строго в копейках (`long`), без `double`.
